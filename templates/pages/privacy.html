Privacy & Data Protection

Secret Ballot Privacy Policy

How BallotBridge safeguards voter confidentiality through double-blind separation.

1. Double-Blind Database Isolation

In ordinary web applications, user actions are stored with a direct reference to the user's primary key (e.g. user_id). For confidential elections, this violates the fundamental secret ballot requirement. BallotBridge solves this by maintaining two completely uncoupled tables:

  • Ballot: Records only the election_id, candidate_id, and an anonymized SHA-256 hash. Contains zero foreign keys to user accounts.
  • VoterParticipation: Records that user_id participated in election_id and issues a receipt token. Contains zero reference to candidate choice.

2. Coercion Resistance Simulation

Voter participation receipts generated by BallotBridge confirm that you cast a vote, but cannot be decrypted by any party to prove which candidate was chosen. This prevents vote-buying and intimidation by ensuring that voters cannot be compelled to surrender proof of their specific selection.

3. Password Security

Passwords are never stored in plain text. BallotBridge utilizes Django's PBKDF2 with SHA-256 password hashing with individual cryptographic salts. Passwords cannot be viewed or recovered by system administrators.

4. Demonstration Nature

Data collected within this environment is strictly used for software simulation and evaluation purposes. No real national or personal financial identification is requested.
